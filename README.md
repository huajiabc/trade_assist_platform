# PA / SMC AI Trading Assistant MVP

本地运行的行情研究工作台：导入 CSV，用交互式 K 线图查看 PA/SMC 结构，并以经过校验的 JSON 连接 AI 分析。初始仓库为空，使用 React 19 + TypeScript + Vite、TradingView Lightweight Charts 5、Express 5。所有 K 线、区域与标注均由结构化数据通过代码绘制，没有生成式图片环节。

## 启动

需要 Node.js **22.12 或更高版本**（建议 Node.js 22 LTS）。在项目目录执行：

```powershell
npm install
npm run dev
```

浏览器打开 <http://127.0.0.1:5173>，默认自动连接 **SNDKUSDT 5 分钟真实行情**。Vite 将 `/api` 同源代理到 `127.0.0.1:3001`。连接等待或失败时显示空态与重试入口，绝不自动填入示例 K 线或模拟分析。公共行情不需要密钥；导入 CSV 仍可独立使用。

合成样例仅在「导入 CSV」面板手动选择，或明确打开 `/?demo=smc`、`/?demo=pa` 时载入，用于离线开发验收；日常入口不使用样例。`?live=标的&interval=周期` 优先于 `demo` 参数。只有手动点击「AI 分析」才调用模型，打开真实行情不会自动消耗 Codex/API 额度。

生产构建和本地运行：

```powershell
npm run build
npm start
```

此时打开 <http://127.0.0.1:3001>。`npm start` 由服务端托管 `dist/`，运行时使用 TypeScript 的 `tsx`，因此安装时需保留 devDependencies。请先构建，不使用 Vite preview 充当 API 服务。默认仅监听本机。

检查：

```powershell
npm test
npm run build
```

单元测试和浏览器测试默认均只使用 **1 个 worker**，测试文件串行执行，避免按 CPU 核数启动大量进程。本地验证请依次运行测试和构建。

内存紧张时可在**单独的 PowerShell 终端**使用构建产物验收，减少开发服务器和模块转换的内存开销：

```powershell
npm run build
$env:PORT = '5173'
$env:PLAYWRIGHT_CHANNEL = 'msedge'
$env:PLAYWRIGHT_WEB_SERVER_COMMAND = 'node --import tsx server/index.ts'
npm run test:e2e
```

测试完成后关闭该终端，避免测试用 PORT 影响日常开发。这些环境变量不写入服务端密钥配置。

浏览器验收测试（首次先安装测试浏览器）：

```powershell
npx playwright install chromium
npm run test:e2e
```

如需使用已安装的 Google Chrome，可在 PowerShell 设置 `$env:PLAYWRIGHT_CHANNEL='chrome'` 后执行测试。浏览器测试覆盖导入、模拟分析、图层筛选、结构定位、无效响应拦截与手机布局。

## 使用 Codex 订阅额度分析

项目通过官方 `codex exec` 在本机服务端调用 Codex，复用 CLI 的 ChatGPT 登录。**ChatGPT 登录使用订阅额度；API Key 使用独立 API 账单**，两者不能混为一谈。依据：[OpenAI 身份验证文档](https://developers.openai.com/codex/auth/)、[非交互式调用与 JSON Schema](https://developers.openai.com/codex/noninteractive/)。项目固定安装官方 `@openai/codex` 运行时，不需要从浏览器传入凭据或读取、复制登录令牌。

在项目目录完成一次官方登录，然后启动：

```powershell
npx codex login
npm run dev
```

选择 ChatGPT 登录，网页「分析来源」选择 **Codex 额度**，载入 SNDKUSDT 实时行情后点击「AI 分析」。如果本机已经登录，直接使用即可。在「模型与设置」可以刷新登录状态。公开行情不需要交易所 Key；真实分析仍会消耗当前登录账号的 Codex 用量。

可选服务端设置：

```dotenv
AI_PROVIDER=auto
CODEX_BIN=
CODEX_MODEL=
CODEX_REASONING_EFFORT=
CODEX_SERVICE_TIER=
CODEX_TIMEOUT_MS=180000
CODEX_PROXY_URL=
```

`CODEX_BIN` 留空自动使用项目安装的官方运行时，也可指定官方原生可执行文件的绝对路径（Windows 为 `codex.exe`，不接受 `.cmd`、`.ps1` 或命令字符串）。`CODEX_MODEL` 留空使用 CLI 内建默认模型；填写时必须是账号实际可用的模型 ID。每次分析启动临时的非交互会话，忽略用户 CLI 配置以隔离 MCP、工具和额外指令，不修改全局配置。最大等待 300 秒，默认 180 秒。

指定本项目后续分析使用 GPT-6 Sol、高强度推理和快速模式，在服务端 .env 设置：

```dotenv
AI_PROVIDER=codex
CODEX_MODEL=gpt-6-sol
CODEX_REASONING_EFFORT=high
CODEX_SERVICE_TIER=fast
```

重启后，每次 Codex 调用（包括同快照的有界修正）显式传入 model、model_reasoning_effort 和 service_tier，并启用 features.fast_mode；不会修改全局 Codex 配置或独立 API 模式参数。留空对应参数则保留 CLI 默认值，非法 effort/tier 在服务启动时拒绝。所选模型须支持对应 effort；实际模型与快速档位可用性由服务端决定，失败不会静默换模型或计费来源。模型与设置面板和 /api/health 的 codexSettings 展示的是请求配置，不是远端已采用参数的证明。官方：[配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)、[GPT-6 Sol](https://developers.openai.com/api/docs/models/gpt-6-sol)、[快速模式](https://learn.chatgpt.com/docs/agent-configuration/speed)。Fast 的订阅内额度按标准模式2.5倍速率消耗，购入credits及Enterprise按需使用按2倍计费；不是降低effort来提速。

如果 Codex 网络需要代理，可设置 `CODEX_PROXY_URL=http://127.0.0.1:7890`（请改为自己的代理端口）。它仅设置 Codex 子进程的网络环境，不影响浏览器或独立 API 适配器，也不会自动复用行情代理。不要在代理 URL 中放入用户名或密码。

服务端在调用前确认 ChatGPT 登录，强制订阅登录方式并移除子进程中的 API Key 环境变量；Codex 错误不会切换到 API 或模拟结果。请求包含所选的 **10–300 根已收盘 K 线**（CSV 按用户提供的完成数据处理）、上下文和 Schema。自动模式选取最近最多 300 根，手动模式使用选定的完整范围，不会静默裁剪超长选区。输出还需要通过 Zod、时间引用和价格坐标校验。图表按 JSON 精确绘制结构，界面展示来源、候选/确认状态、依据、失效条件和不确定性。返回的 token 用量为本次分析任务的累计调用用量；发生修正时合计两次，任一调用未提供有效统计则不显示部分用量，**不是订阅余额或金额**。

只有手动点击分析才调用模型；WebSocket 更新价格不会触发付费分析。可以取消分析；关闭请求或切换数据时会中止对应子进程。单个服务实例同一时间只接受一次 Codex 分析，避免重复消耗。此桥接只面向个人本机使用，保留默认 `HOST=127.0.0.1`。

## 独立 API 模式配置

复制 `.env.example` 为 `.env`，在服务端文件中填写 API Key 与明确的模型 ID，然后重启开发服务：

```dotenv
AI_API_KEY=your_server_side_key
AI_BASE_URL=https://api.openai.com/v1
AI_MODEL=gpt-4.1-mini
AI_RESPONSE_FORMAT=json_schema
AI_TIMEOUT_MS=45000
HOST=127.0.0.1
PORT=3001
```

`AI_MODEL` 是配置示例，需使用供应商账户实际有权限且支持所选格式的模型；没有隐式默认模型。`AI_BASE_URL` 为兼容 Chat Completions 的 API 基础路径，程序追加 `/chat/completions`。API Key 只从服务端环境变量读取，绝不使用 `VITE_` 前缀或发送给浏览器。`.env` 已被 Git 忽略。

默认发送 `response_format: {type: "json_schema", json_schema: {strict: true, ...}}`。供应商仅支持 JSON mode 时，可以显式改为 `AI_RESPONSE_FORMAT=json_object`；程序仍将完整 Schema 交给模型并在本地执行相同校验。程序不会在失败后自动切换响应格式。API 格式参考 [OpenAI Structured Outputs 官方文档](https://developers.openai.com/api/docs/guides/structured-outputs)。若供应商不支持 `max_completion_tokens` 或该接口，需要在 `server/provider.ts` 中实现独立适配器。

界面明确选择来源后，真实来源对应 `mode=ai`，模拟对应 `mode=mock`。HTTP 兼容模式：

- `auto`：按 `AI_PROVIDER` 选择；配置为 `auto` 时优先已登录的 Codex，再选择已配置的 API，否则模拟。网页始终发送用户选择的明确来源。
- `mock`：始终运行本地确定性模拟算法，适合验证图表与交互。
- `ai`：必须有所选来源的真实配置，否则明确报错。`provider=codex` 或 `provider=api` 可以明确指定，失败时不会切换来源。

真实调用遇到网络、超时、额度、拒绝、截断、无效 JSON 或坐标校验失败时显示错误，**不会伪装成成功或回退为模拟结果**。默认 API 上游超时 45 秒。只向配置的供应商发送已选择的最多 **300 根 K 线**和用户填写的上下文；其余导入数据仅用于本地图表。没有配置真实密钥时，测试通过替身传输验证 API 协议，不能代表供应商连通性验证。

## 真实行情：SNDKUSDT

模型返回可解析 JSON 但未通过结构或行情证据校验时，服务端会把具体校验反馈与前次结果发回同一供应商，针对同一固定快照最多修正 **1 次**。前次结果超过 64 KiB、网络/鉴权/拒绝/截断/JSON 解析失败或任务已取消时不自动重试；修正仍未通过则明确报错，两份无效结果均不渲染。两次调用共享原有超时总预算；实时新 K 线不会进入修正输入。界面在分析中说明最多两次调用，成功响应的 `analysisAttempts` 标记实际次数，Codex 用量在两次都有有效统计时合计。模拟模式不调用修正流程。

模型上下文保留交易所原始小写周期（例如 `1m`），另附实际等距 K 线的 `intervalSeconds`（1 分钟为 60）；图表显示用的 `1M` 不再传作模型周期。PA 突破回踩的确认仍严格要求多头收盘高于整个阻力带上沿、空头低于支撑带下沿，候选状态不会绕过形态与坐标校验。

在界面「交易所行情」栏填写 `SNDKUSDT` 并点击「加载行情」，即可通过服务端读取 **Binance USD-M 的 SNDKUSDT 股票挂钩 USDT 永续合约**。这是交易所衍生品行情，价格与成交量口径均来自该合约，并非纳斯达克 SNDK 股票的直接报价，也不是现货币对。其他可用的 USDT 合约也可输入交易对后读取。此功能只使用公开行情接口，**无需交易所 API Key**，没有账户、余额或下单能力。

支持 `1m`、`5m`、`15m`、`1h`、`4h`、`1d` 周期，默认最近 300 根，单次限 20–500 根。初次通过 REST 加载历史，再通过交易所 WebSocket 接收当前 K 线更新（交易所有更新时约 250 毫秒推送），经本地 SSE 推给浏览器。实时连接期间每 60 秒通过 REST 校正，断线期间每 30 秒同步历史并自动尝试重连；也可手动刷新或暂停。图表显示交易所尚未收盘的末根 K 线，但分析时排除该末根。每次分析固定一份输入快照：同标的、同周期的实时更新不会取消正在进行的请求，也不会抹除已有结果或错误。结果区显示快照截至时间；自动范围新增 K 线、原范围被修订或离开历史窗口时提示复核。手动历史选区后方的新 K 线不改变该选区。时间或价格依据已经无法在当前图表对应的标注会隐藏，原始快照和结果仍保留供复核、导出。切换标的/周期或导入另一份数据会中止旧请求，迟到结果不能污染新数据。获取失败时保留已有画面并标为过期，不会自动替换成合成数据。

`GET /api/market/candles?symbol=SNDKUSDT&interval=1h&limit=300` 是本地只读接口。服务端调用固定的 Binance `/fapi/v1/klines` 和 `/fapi/v1/time`，使用交易所时钟判断末根收盘状态；校验 UTC 周期、严格递增时间、OHLC、成交量、数值和响应大小后才发送给前端。上游单次超时 10 秒，并设 5 秒有界内存缓存与相同请求合并。时间缺口和不足的历史不会补齐。接口格式见 [Binance USD-M 官方行情文档](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/market-data)。

`GET /api/market/stream?symbol=SNDKUSDT&interval=1h` 为同源 `text/event-stream` 接口，事件为 `status`（连接状态）和 `kline`（通过校验的结构化 K 线）。上游使用当前 Binance `wss://fstream.binance.com/market/ws/sndkusdt@kline_1h`，详见 [Binance Kline WebSocket 官方文档](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/ws-streams/market#klinecandlestick-streams)。只有收到首条有效行情才显示已连接；15 秒无有效更新即标为过期并重连。畸形、错误标的/周期、错误时间边界、超过服务器时钟 60 秒及矛盾 OHLCV 均被拒绝；旧事件和重复事件不延长新鲜度。连接关闭后使用 1–15 秒有上限退避；网页断开即释放上游与定时器。每个服务实例最多 8 个实时页面，单帧上限 64 KB、慢客户端缓冲上限 256 KB。SSE 的 15 秒注释心跳只维持传输，不能证明价格仍在更新。订阅不包含逐笔成交、盘口或交易账户数据。

如果本机 Node.js 直连交易所不可用，可以在服务端 `.env` 配置 `MARKET_PROXY_URL=http://127.0.0.1:7890`，指向自己已有的 HTTP/HTTPS 代理，再重启服务。代理配置不会发到浏览器。交易所连接受到网络、服务可用性和上游限流影响，遇到错误时页面给出具体提示，不回退模拟行情。


可直接打开 <http://127.0.0.1:5173/?live=SNDKUSDT&interval=1m> 连接 1 分钟行情；页面仍默认打开 5 分钟周期。`1m` 是交易所原生 K 线，沿用同一套 REST、WebSocket、指标和已收盘分析流程，不由其他周期重采样。浏览器外部连通性测试需显式设置 `LIVE_MARKET_SMOKE=1`；常规测试使用固定行情响应，不依赖交易所网络。可通过 `npx tsx --import dotenv/config node_modules/vitest/vitest.mjs run tests/realtime.test.ts` 在设置该变量后执行真实 WebSocket 验收（需在 25 秒内收到两条有效更新）；此命令读取服务端 `.env` 中的行情代理。无交易更新或上游不可达时会明确失败，不回退模拟数据。

## CSV 格式

必需列为 `timestamp,open,high,low,close,volume`，允许调换列序。可从界面下载完整示例 CSV。示例是用于演示的**合成数据**，不代表实时行情。

```csv
timestamp,open,high,low,close,volume
2026-10-10T00:00:00Z,100,103,99,102,1200
2026-10-10T01:00:00Z,102,104,101,103,1300
```

以上仅展示格式，完整文件至少需 10 行行情。支持带时区的 ISO 8601，以及 Unix 秒或毫秒；内部统一转换为 **UTC Unix 整秒**。无时区日期、非法日期、缺失值、非数值、重复/逆序时间、负成交量和矛盾 OHLC 会被拒绝，不会自动排序或补齐。时间间隔不一致时保留原始时间并提示。一次导入限 **10–2000 根**，服务端另有 **2 MB** 请求体限制。

## 行情缓存与研究历史自动归档

图表行情和导入 CSV 使用有界内存窗口；浏览器研究状态使用 IndexedDB `pa-smc-research` 本地持久化。服务端公共行情缓存仍按原有有效期和数量上限淘汰，不在本轮增加历史 K 线文件或外部数据库。

研究历史达到工作集阈值后自动归档，不再冻结市场更新，也不要求新建聊天或清空当前研究记录。常用工作集保留各周期最近 8 份快照、最近 64 条状态历史、24 次策略评估、8 次解释、1600 条事件及当前事实最近 2 个版本；原计划所有历史版本引用的快照、计划关联事件、当前解释所需快照和事实另外保留，因此这些是软目标，不会为满足数量而切断引用。完整旧快照、事实版本、解释、策略评估和事件写入同一 IndexedDB store 的独立归档键。

归档与精简后的工作区在同一个读写事务中提交，成功后才替换内存工作集；失败保留原记录并显示错误。持仓登记、交易所持仓与原计划的显式关联、计划版本、原始价位和确认时间均不由归档修改。计划跟踪所需的实际 1m K 线独立保留，沿用原有最多 300 根待触发和额外 300 根观察规则；最新行情中的真实缺口不会被旧快照偷偷填平。旧版 `capacityReached` 状态载入后自动解除，只恢复本地规则更新，不触发模型调用；真实数据修订和缺口提示仍保留。

「研究详情与工具 → 导出研究状态」导出当前工作区及该标的/来源的全部本地归档，JSON 在原 `exportVersion: research-evaluation-1.0` 结构上增加 `archiveFormat: research-archive-1.0` 和 `archives`，按 `sessionId`、结构/快照 ID、原始版本及可知时间关联。面板展示近期记录，较早的完整记录可在导出中查看。清除当前研究记录是单独的确认操作，不会由归档自动触发，已有归档保留。

归档占用浏览器本地磁盘空间，未实现自动删除旧归档或跨设备同步。浏览器配额用尽时会提示备份；导出在最近一次保存失败后仍包含内存中的当前记录。大量归档的完整 JSON 导出可能较大，当前未提供流式或压缩导出。不要通过清除网站数据来代替导出备份。

2. 选择 Codex 额度、API Key 或模拟，点击 AI 分析。当前来源和调用用量会在结果处明确展示。
3. 图表支持缩放、平移与十字光标。PA 采用触点色带、箱体、推进回撤带、形态烛线框及突破阶段路径；SMC 保留摆点、破位事件与 FVG/OB 区域。
4. 使用结构类型开关显示/隐藏标注；点击分析结构可定位相应 K 线并高亮。候选与确认结构使用不同样式，面板展示依据、失效条件、不确定性与机会风险。

## 选择分析范围与查看任务状态

- **自动范围**：选取最近最多 300 根已收盘 K 线，显示实际起止 UTC+8 时间和根数。实时行情的未收盘末根始终排除。
- **手动范围**：启用图表选区工具，在 K 线区拖选起止位置，也可点选两端或编辑起止时间。图表使用真实 K 线时间绘制选区；左右反向拖选同样支持。普通模式保留拖拽平移和缩放，退出选区工具即可继续浏览。
- **图表内操作**：选择范围后可直接点击“分析所选范围”；使用“定位选区”缩放到已选区间，专注图表模式下也可完成选择和分析。
- **范围限制**：少于 10 根、超过 300 根、缺少有效端点或选区已移出加载的历史窗口时，显示具体原因并禁用分析。手动范围不会自动替换成最新行情，也不会悄悄缩短。
- **分析任务**：点击后立即显示来源、固定输入根数、截至时间、已等待时长与取消入口；结果面板和专注图表内均有状态反馈。不显示虚构的完成百分比。失败保留明确错误供重试，取消给出确认状态。

实时价格继续更新，不代表模型在持续重新分析。新的模型请求仅由手动点击触发；已有分析描述的是所标明的快照。

AI 会先审阅所选范围的前、中、后三段，再选择有依据的主要历史波段、转折和局部结构；正常只调用一次模型；结果校验失败时最多追加一次修正调用。历史 PA/SMC 复盘与末端的当前交易候选分开处理，不把历史计划显示为现在的开仓信号。图表上方的“历史标注分布”统计原结果中锚定于各段的结构数量（按结束或事件时间计数），不随显示开关变化，也不是逐根分析覆盖率。蓝色选区表示提交的输入范围；某段没有标注不代表没有结构或已经完整排除机会。旧结果需要手动重新分析才能使用新的全段审阅提示。

“已确认”仅表示在当前数据内符合所用结构规则，不保证未来走势。摆动点确认需要右侧 K 线，存在确认延迟。模拟算法采用简化规则，只用于演示数据链路与标注交互，不是完整交易策略；AI 结果也必须由使用者复核。

## 规则 FVG / OB 图层与 AI 参考

加载真实行情或导入 CSV 后，规则图层即自动计算，无需调用 AI。FVG、OB 候选分别可显隐，历史回补/失效区域默认隐藏。点击区域中央小字、区域位置或展开“原理与识别依据”列表可定位，查看精确价位、形成时间、首次触及及失效条件。它与模型生成的 PA/SMC 标注、显示候选开关和分析视图相互独立；规则来源、方向、状态和依据在面板展示。

FVG 和 OB 色带最多向右延伸 **5 根实际 K 线**：规则区域从形成根计算，模型返回区域从其起点计算；提前回补或失效则提前结束，尚无后续行情时不补造未来时间。此限制仅改变绘制、命中和定位范围，原始生命周期与后续状态继续完整跟踪，并继续用于 AI 参考。

两类区域统一使用无边框的半透明填色，中央只写 9px 的 `FVG` 或 `OB`，不显示外置标签、引导线或中线。区域太窄或太薄时隐藏文字，放大到足够空间后再显示，不把文字挪到区域外。新形成的规则区域先占自身一个 K 线单元，随后最多延伸 5 根。

- **FVG**：三条相邻已收盘记录中，多向要求第三根 low > 第一根 high，且中间根 close > 第一根 high；空向对称。区域为第一根与第三根的影线缺口，50% 中点仅为几何参考。形成后按后续影线追踪最大回补比例，触达远边界记为完全回补；不预测价格一定回补。
- **OB 候选**：严格左右各 2 根确认摆点，在确认根之后才允许收盘突破；取突破前 12 根内最后一根反向非 doji K 线实体为区域。首次后续相交标为已测试，多向收盘低于下沿、空向收盘高于上沿才失效。这里使用实体版定义，不证明机构订单，不要求一定存在 FVG。
- **形成与起源**：OB 起源蜡烛早于 BOS，FVG 起源是三根中的第一根；色带从形成根开始绘制，起源时间保留在依据列表。界面时间使用 K 线 UTC+8 开盘时间，原始 Unix 时间戳不变，须等对应形成根收盘才可知。未收盘末根不参与形成、触及或失效计算；缺失行情不补齐，结果受加载历史窗口影响。
- **AI 参考**：API 与 Codex 都在服务端按本次所选的最多 300 根行情重算 `ruleIndicators`，包含规则参数、精确边界、形成与生命周期、证据时间、来源和省略数量。单次最多 32 项（每类 16 项，优先当前区域并分散保留历史），原始行情不采样。模型可采纳、质疑或忽略规则参考，OHLCV 仍是主要依据；图层开关不会修改模型输入，也不会自动触发模型调用。旧模型结果不会因新增规则而自动重写，需要手动重新分析。

本实现按公开描述独立编写，采用明确的一组规则，而非声称复刻某个商业指标。参考作者说明：[LuxAlgo FVG](https://www.tradingview.com/script/jWY4Uiez-Fair-Value-Gap-LuxAlgo/)、[Smart Structure Breaks & Order Blocks](https://www.tradingview.com/script/8jb0Cnzm-Smart-Structure-Breaks-Order-Blocks/)。原生绘图使用 [Lightweight Charts Series Primitives](https://tradingview.github.io/lightweight-charts/docs/plugins/series-primitives)，所有时间/价格坐标均来自结构化数据。

## PA 分析与可视化

PA 与 SMC 是可独立显示的证据层。PA 面板先描述上行、下行、区间或转换状态，再展示下列对象；点击任意条目会开启相应图层并定位到证据 K 线。

| PA 对象 | 图表表达 | 数据校验 |
| --- | --- | --- |
| 支撑、阻力、震荡区间 | 有边界的填充色带或箱体、真实触点 | 时间、价格与触及记录在输入窗口内；确认支撑阻力需重复触及，区间需上下两侧重复触及 |
| 推进、回撤 | 方向带、箭头与端点 | 起止 K 线存在、时间有序、端点匹配实际高低价、方向与价格一致 |
| Pin bar、吞没、内包 | 对应单根或双根 K 线高亮框 | 根据原始 OHLC 验证主影比例、相邻反色实体包含或严格内包 |
| 突破与回踩 | 突破、回踩、确认的阶段编号与路径 | 引用先前形成的价区；收盘越界、后续触及边界、确认收盘站稳均需实际证据 |

导入面板中的「PA 教学示例」或明确的 `/?demo=pa` 载入 `shared/paSample.ts` 生成的 120 根合成行情，包含重复区间边界、突破回踩及明确的蜡烛形态。可下载 `public/pa-example.csv` 再导入体验；它不是历史或实时价格，不在默认工作台自动载入。原 BTC 合成示例仍可在导入面板或 `/?demo=smc` 使用。所有模拟分析都从当前输入行情计算几何，不向无形态的行情强加标签。

本项目采用明确且保守的 MVP 规则，并不声称 PA 存在统一的形态阈值。Pin bar 主要影线至少占全幅 60%、至少为实体两倍，反向影线不超过 25%、实体不超过 35%；吞没要求相邻反色实体严格包含；内包要求当前高低均严格位于母线之内。区间/支撑阻力使用重复触及证据，不等于已经证明未来有效。概念参考 [Fidelity 的支撑阻力说明](https://www.fidelity.com/learning-center/trading-investing/technical-analysis/support-and-resistance?print=true-0)。原生标注使用 [Lightweight Charts series primitives](https://tradingview.github.io/lightweight-charts/docs/plugins/series-primitives)，随图表缩放、平移及价格坐标转换重新绘制。

Schema 1.2 起增加必需的 `priceAction` 对象，其中包含 `regime`、`summary`、`zones`、`legs`、`patterns`、`breakouts`。没有证据的数组应为空，模型不必补齐类型。严格旧版 1.0/1.1 结果迁移为空 PA 层，不从旧文字推断图形。机会与数值计划可引用 PA 或 SMC 的 ID；同样执行时间、价格和引用校验。真实 Codex/API 与模拟使用同一 Schema。

已确认的形态表示输入数据支持该形态；推进/回撤及市场状态仍是分析判断。任何未来开仓情景始终为候选。当前尚未实现完整 Brooks PA 体系、楔形/双顶双底等全部形态、通道拟合、逐根回放或策略回测。

## 关键价位水平线

AI 返回的关键价位以细虚水平线叠加在价格图上，右轴显示对应价格，可用独立「关键价位」开关显隐，不受 PA/SMC 视图或候选结构开关影响。点击右侧价位条目会高亮对应水平线，并在需要时扩展价格范围；点击图中的线可回选条目。水平线仅表示模型给出的价格参考，依据保留在结果面板；关键价位没有时间字段，因此不虚构时间锚点，也不改变当前横向视野。

## 开仓候选、盈亏区域与流动性扫除

在图表「开仓候选 / 盈亏区间」和「流动性扫除」开关中独立控制新图层。在「潜在观察计划」选择数值计划，可定位参考入场标记及红色风险区、绿色收益区；多个目标分别显示 TP1–TP3 和对应 R 倍数。同一时刻只绘制一份选中的数值计划，保持 K 线清晰。在「流动性扫除」点击记录，可定位参考摆动与扫除影线，查看识别依据和失效条件。

图表上方的开仓计划状态条显示模型返回、当前可绘制和因历史依据失效而隐藏的数量，并提供定位、切换方案和恢复图层操作。文字观察与含入场/止损/目标的数值计划分别计数；仅有文字观察不会绘制虚构的价格。分析始终对应原始输入快照，历史选区中的候选不代表当前实时行情仍然适用。

Schema **1.3** 增加必需的 `tradePlanning`（`status`、`reason`）和每份数值计划的 `trigger`。`conditional` 表示有数值候选，`watch-only` 表示只有文字观察，`no-setup` 表示两者均无。模型必须说明这次规划判断的具体依据；触发条件尚未满足时，若已有价格结构支持，仍可返回待触发的数值候选。有待确认条件并不自动排除候选，也不会为凑齐显示强行生成计划。界面分别提示模型未提供计划、图层关闭及历史依据已隐藏。严格旧版 1.0/1.1/1.2 结果先按原合同校验再迁移；无法恢复的触发说明会明确标为旧格式未提供，不推测交易条件。

- **开仓候选**：参考入场价、计划止损与目标均为有条件的研究假设，状态始终为 `candidate`，不表示成交或订单。时间锚点必须等于本次输入最后一根 K 线；真实行情使用最后一根已收盘数据。图形向右的宽度只是展示空间，不是预测的开仓时间，也不生成未来 K 线。
- **盈亏比**：`R = 目标收益价格距离 / 止损风险价格距离`，例如 `2R` 表示风险∶收益为 `1∶2`。多头使用 `(目标−入场)/(入场−止损)`，空头使用 `(入场−目标)/(止损−入场)`，与 [TradingView 多空头绘图工具的公式](https://www.tradingview.com/support/solutions/43000475660-how-to-use-long-and-short-position-drawing-tools/)一致。多目标分别计算；对数价格轴下仍按真实价格计算，不使用屏幕高度计算。未计入手续费、点差、滑点、资金费用；没有持仓数量，因此不显示账户实际盈亏或胜率。
- **流动性扫除**：这是基于 OHLC 的价格行为代理。买方参考已确认摆动高点，要求后续 high 严格越过该价；卖方参考已确认摆动低点，要求后续 low 严格越过该价。只有该根收盘返回参考价内侧才标为已确认形态，否则为候选。参考摆动需要左右各 2 根确认，且参考点确认后到本次扫除前不能已有收盘突破。标记精确使用原始 high/low 与时间；它不证明存在或成交了实际止损单，也不等同于订单簿流动性数据。

Schema 1.1 起包含必需的 `tradeSetups` 与 `liquiditySweeps` 数组，后续版本继续保留。没有足够证据时允许为空。旧版 1.0 结果可读取并迁移为空数组，不从文字中推测入场和止损价格。多空价格顺序、非零风险距离、有限盈亏比、目标递进顺序、引用 ID、真实扫除坐标与收盘证据都会在服务端与前端校验；无效输出拒绝渲染。

内置合成示例不需要模型额度，包含候选计划与可核验的扫除案例。选择 Codex 或 API 后，仍只有点击「AI 分析」才调用模型。升级图层本身不触发自动分析。

## 条件计划的行情跟踪

Schema **1.4** 为每个数值计划增加必需的 tracking 字段，可为 null。非空时包含 1–4 个依序步骤（每步 1–3 个同根 AND 条件）、确认前取消规则和 1–300 根已收盘 K 线的等待期限。规则支持影线与价格区域相交、收盘严格高于或低于阈值；下一步必须使用更晚的 K 线。收盘达到取消价或影线触及取消价时优先取消候选。只有能完整表达模型文字条件时才启用自动核验，任意形态、盘中路径或其他无法表达的条件保留为人工确认。严格旧版 1.0–1.3 按原合同校验后迁移为 tracking: null，不从旧文字补造规则。

前端使用快照之后的已收盘行情在本地回放，实时未收盘末根不进入判断，不调用额外模型。状态包括待触发、条件已满足、候选失效/过期、参考 SL 或全部目标触及、同根顺序不明和数据需复核；详情展示每一步规则、事件时间与价格，图表以真实坐标绘制事件标记，终止或需复核的计划区域会淡化。模拟几何计划仍需人工确认，不伪造触发规则。

条件在收盘时才可知，该根更早的 high/low 不计为条件满足后的 SL/TP 事件；后续同根同时覆盖参考 SL 和新目标时记录为顺序不明，不认定哪方先发生。目标触及只表示后续价格到达参考位置，不证明入场、订单成交或实际收益。未满足条件的等待窗口允许在最后一根完成确认；条件满足后另外最多观察 300 根。分析生成前已经存在的右侧行情也可能进入历史回放，不将回放事件宣称为当时可用的实盘信号。

核验依据仅为当前载入的已收盘窗口，缺口、逆序、重复、原分析 OHLC 修订或观察上限会要求复核；没有自动补齐缺失行情。每次按最新数据重新计算，后续行情修订可改变回放结果。滚动窗口丢失早期核验记录时暂停，尚无跨刷新历史持久化。JSON 导出保留原分析、输入快照以及独立的 trackingReview（本轮核验结果和所用已收盘行情），便于复核；该核验对象不改写 AI 原结果。

## 分层与扩展

- `shared/market.ts`：OHLCV 类型、CSV 解析、数值/时间/缺失值校验和长度限制。
- `shared/liveMarket.ts`：行情请求/响应合同、周期与末根收盘状态校验、分析窗口选择。
- `shared/realtime.ts`：实时事件合同、重复/逆序事件过滤、历史窗口合并与缺口检测。
- `shared/analysis.ts`：Zod 结构合同、由同一合同生成的 JSON Schema、引用与坐标校验。
- `shared/priceAction.ts`：PA 对象合同、实际 OHLC 形态与区域/事件校验、确定性 PA 分析。
- `shared/paSample.ts`：可重复的 PA 教学行情，与原有合成样例分开维护。
- `shared/tradeGeometry.ts`：多空方向一致的真实价格风险、收益、R 倍数与百分比计算。
- `shared/mock.ts`：可重复的离线结构演示。
- `server/provider.ts`：独立的 `AnalysisProvider` 适配接口和 OpenAI-compatible 实现。保留 `ScreenshotInput` 类型边界；当前 HTTP 路由仅接受行情与上下文，不接收或上传截图。

### 全区间规则目录、分层研究与显示（Schema 1.5）

- 复用现有原生 Chart Primitive：三个总开关分别控制主结构、辅助证据和交易计划；原有 PA/SMC 视图及细分类开关继续生效。规则摆点和破位不依赖模型先返回。主结构文字缩短为类型，按缩放和画布宽度分配标签预算；优先选中项、5/5主要结构和破位。各 Overlay 共用标签占位，尝试不同文字行并避让实体；过密时只抑制文字/局部绘图，真实坐标和目录不变。极端密集时选中标签可优先显示；不能保证任意缩放下每个标签都同时可见。
- 规则目录同时计算严格左右2/2与5/5摆点，比较同尺度前一同侧摆点得到HH/HL/LH/LL。只有摆点右侧确认之后首次收盘越过最近未破位摆点，才记录该尺度BOS；突破方向与此前相反记CHoCH。这是明确的研究定义，并非所有PA/SMC流派的统一标准。连接相邻异侧确认摆点的趋势腿复用现有PA Overlay。FVG/OB继续复用原规则模块，OB只标候选，不代表机构订单。
- 每80根一个核心窗口，左右各24根重叠上下文；局部规则扫描后与全区间扫描按绝对时间、尺度、方向和事件坐标ID整合。全段记录拥有分类权，补回局部窗口因缺少先前趋势/摆点而遗漏的事件；局部结果不能覆盖全局分类。FVG/OB本身已扫描完整输入，不重复实现局部区域算法。完整规则目录无尾段截断。
- originTime为历史起源，formedAt为形成根，confirmedAt为确认根，resolvedAt为首次回补或失效根。它们全部使用原行情K线的开盘时间坐标；依赖收盘的结论必须等相应K线收盘才可知。历史起源不会冒充当时可用信号。区域延伸仍上限5根，绘制期限与生命周期分别保留。
- 服务端先确定性提取，再按历史窗口轮转、主要结构优先选取参考，预算为min(72,24+floor(N/6))，同时给主要趋势腿及既有FVG/OB参考；全部OHLCV仍完整传入。按类型与区间长度分配输出预算，例如主结构约12+floor(N/12)、上限40，长区间PA腿最多16，计划仍最多2个。预算是上限，不是必须生成的数量。
- **调用成本**：分窗计算在本地完成，模型仍只有一次全局整合调用；沿用最多一次无效结果修正、同一总截止时间、失败不切换计费来源的机制。不会为每个窗口独立调用模型。输入规则参考会增加Token，实际用量以结果面板为准；没有历史真实模型对照评测，不能声称模型识别准确率已经提高。
- 新 research 顺序为市场状态及引用、全段背景、区域价格反应、末端情景、条件式计划。模型可以质疑规则、留空类别或明确等待。区域测试必须实际相交，收复必须满足相交及方向收盘；不凭区域存在断言反应。同次位移参考的事件组用于提示相关性，不表示统计独立证据。
- 有阶段研究的计划必须包含 basis：情景ID、入场、止损及逐目标结构ID；所有锚点也须包含在计划引用中。入场须在引用区域或近期20根平均振幅四分之一内，止损位于保护结构外，目标落在引用价位/区域；纯趋势腿或烛线形态不能单独成为精确价位锚点。第一目标不足1R则拒绝阶段计划。止损现在使用下述ATR与结构外缓冲校验，原“6倍平均振幅”硬上限已移除，避免为通过上限而压紧止损。手工形态条件仍可tracking=null，明确需要人工核验。
- Schema **1.5** 添加可空 research、逐计划可空 basis，保留1.4的tracking。严格1.0–1.4按旧合同校验后迁移；不补造旧结果缺失的确认时间、情景、价位依据或触发规则。research=null的旧版、模拟或不完整结果仍可查看，但界面明确提示阶段研究未提供，不能当作已完成上述关联校验的计划。完整新阶段结果中的确认结构和FVG/OB须匹配规则证据；确认时间不能核验时拒绝并允许一次模型修正。
- “来源与覆盖”分别展示完整规则数量、规则参考预算、分析返回与当前坐标投影保留数量；原“历史标注分布”仍只统计原分析返回。模型的窗口取舍是自述，不能据此判断遗漏属于未识别还是未展开。缩放密度提示只解释当前显示策略。点击规则目录或引用定位原时间/价位；详情展示形成、确认、失效及依据。JSON导出额外保存独立ruleReview，不改写原模型结果。

自动化回归新增结构范围60/168/299根、窗口边界和稳定ID、按前缀核验真实确认时间、规则引用投影、阶段计划价格与反应校验、旧1.4迁移、标签预算/避让/图层切换及浏览器定位。浏览器使用受控模拟结果验证界面，不能替代真实模型输出质量评测。不会自动开仓或发送订单。

### 止损结构与波动检查

- shared/tradeRisk.ts 对分析快照计算 ATR(14)，使用包含前收盘跳空的 True Range，前14根SMA初始化后按Wilder/RMA平滑；不使用快照之后的数据、不合成更高周期。算法定义参考 [TradingView ATR 文档](https://www.tradingview.com/support/solutions/43000501823-average-true-range-atr/)。少于14根或ATR为零不能提供完整阶段数值计划，仍可返回观察。
- 完整阶段计划须先选择有依据的失效结构，止损越过其不利外沿至少0.25 ATR，入场到止损距离至少0.5 ATR；0.01价格单位越界不再视为充分缓冲。低于1 ATR、超过6 ATR分别提示噪声敏感与周期/目标复核，后者不再是硬上限。所有计算统一引用STOP_RISK_POLICY；这些是项目过滤参数，未经回测，不是通用最优止损、概率或收益保证。
- 真实保护结构与缓冲确定后仍须第一目标至少1R且有实际结构引用；空间不足就等待。服务端仅接受或拒绝，不自动移动入场、止损、目标，不伪造更高盈亏比；已有一次有界修正机制可让模型重新审阅或返回空计划，不增加额外调用。
- 面板显示绝对价格风险距离、百分比、对应周期ATR倍数、保护结构外沿和实际缓冲。使用原分析快照，行情更新不移动止损。旧版/模拟的basis=null计划继续可见，但明确提示缺失结构依据及过窄风险；不补造保护结构。没有盘口/最小跳动/点差与滑点数据，不保证过滤后可成交或不会被正常波动触及。


## 多周期持续研究工作台（research-1.0）

- **数据合同**：shared/researchData.ts。每周期携带来源、周期、收盘依据、末根已收盘开盘时间、observedAt和原始OHLCV；程序重新检查数值、顺序、边界、缺口、样本量、延迟与共同截止时间。周期缺失或请求部分失败保留空缺并降级，不回填过期行情或示例。


凭据只有服务端环境读取，没有浏览器录入/读取密钥接口，不写入localStorage/IndexedDB或研究导出。若使用`.env`文件，应将文件读写权限限制到运行服务的本地用户（Unix可`chmod 600 .env`，Windows在文件安全属性中限制访问）；环境变量是首选。不引入额外数据库或远程密钥服务。网络代理沿用服务端`MARKET_PROXY_URL`，不会改变现有7890配置。

若启动环境已有同名变量，默认会优先于本地`.env`。需要明确使用本项目的本地配置时，运行`npm start -- dotenv_config_override=true`；端口由该文件的`PORT`决定。此选项只影响本次服务进程，不修改系统环境变量。

3. 打开「模型设置」中的「Binance USDⓈ-M · 只读账户」，点击「测试并连接」。程序实际签名读取账户及持仓，成功后由后端每15秒同步。启动或刷新页面不会自动连接账户。可手动刷新、断开和重新测试连接；正常短时间重复刷新合并，失败会退避，限流遵守Retry-After。45秒未成功更新、请求失败、重连未完成或断开时，旧快照明确标记过期/断开，不会变成零持仓。

对Binance的出站适配器仅允许固定`https://fapi.binance.com`上的七个GET：

| 接口 | 用途 |
| --- | --- |
| `/fapi/v1/time` | 实际交易所时间、签名偏差校正 |
| `/fapi/v1/exchangeInfo` | 合约类型、baseAsset数量单位、保证金币种 |
| `/fapi/v3/account` | 余额及初始保证金、账户/持仓交叉核验 |
| `/fapi/v2/positionRisk` | 实际均价、数量、标记价、未实现盈亏、杠杆、保证金模式、强平参考 |
| `/fapi/v1/positionSide/dual` | 单向/双向持仓模式 |
| `/fapi/v1/openOrders` | 现有普通挂单及限价减仓，只读 |
| `/fapi/v1/openAlgoOrders` | 现有Algo条件单、SL/TP与移动止损，只读 |

适配器的公开调用入口与最终HTTP入口均检查白名单，HTTP方法固定GET；无任意URL/endpoint转发能力，无下单、改单、撤单、转账、提现、改杠杆或保证金代码。应用自己的POST仅控制本地连接/刷新/断开/人工审阅，不是交易所执行请求。请求使用HMAC SHA256、毫秒timestamp和5000ms recvWindow；时间错误最多校正一次，单次同步总期限12秒。原始错误文本、完整签名URL、头部和凭据不返回、不记普通日志。账户API还限制为本机同源访问，不提供远程账户或多用户授权。

### 真实持仓工作流

在右侧「持仓管理」选择交易所持仓。BOTH/LONG/SHORT按原始positionSide分别保存，未合并对冲多空；数量单位来自交易规则，不将positionAmt武断解释为合约张数。零仓位、缺少数据、失败及旧快照分开显示。账户和positionRisk的非零记录/数量不一致时暂停审阅；REST读取并非原子事务，期间发生变化需重新同步。

原计划必须由用户明确选择，关联记录固定当时计划版本；数量、均价、保证金或杠杆变化后需重新确认。观察到平仓后再出现的仓位具有新的实例ID，不继承旧关联。交易所仓位不进入本地手动登记数组，也不被候选触发自动创建。账户数据只留在后端和浏览器内存，研究持久化仅保留非凭据的关联ID、原计划版本与变更事件。

快速扫描会优先提示相关5m保护失效、15m结构冲突或原目标空间消耗；普通K线与账户轮询均不调用模型。「深度审阅此持仓」才把所选仓位、相关币种余额、必要风险字段、明确关联的原计划版本以及多周期行情发送给已选AI适配器，不发送API Key/Secret或其他持仓。账户/行情时间相差过大时拒绝审阅；模型运行期间发生变化后，结果只属于原快照。更换账户、标记价/仓位变化、行情或状态版本变化、断开及过期都会使旧建议不再显示为当前。

建议使用独立position-review-1.0 Schema。支持继续观察、保护复核、TP/分批止盈复核、假设风险或证据不足；每项有结构/周期引用、变化、确认与重新评估条件。精确保护参考只允许真实5m主要结构外的既有ATR缓冲，目标只允许有效5m/15m实际结构；方向、顺序和剩余风险空间仍受校验。没有结构、保护或目标空间就不给精确价格。R使用实际开仓成本或当前剩余风险，交易所未实现盈亏与本地价格估算分开展示，缺少手续费/资金费不自动补算。强平距离不是强平概率，所有建议只供人工复核，未执行任何操作。

已知边界：仅HMAC、主站USDⓈ-M REST轮询；不支持Portfolio Margin、账户WebSocket、自动订单或真实成交明细。现有图表行情适配器仅支持USDT合约，其他USDⓈ-M仓位可看账户数据但不会伪造对应PA/SMC背景。未在两次轮询间观察到的瞬间平仓重开无法由REST恢复完整成交生命周期。大模型审阅较慢时结果可能已过时，需要结合当前本地规则和人工复核。未接入资金费/手续费归因、统计回放或回测。

自动化测试全部注入HTTP/模型响应。浏览器测试默认拦截账户及AI请求，禁止真实账户访问和额度消耗；本机已有Chrome时可使用`PLAYWRIGHT_CHANNEL=chrome`运行，无需额外安装浏览器。

### 持仓图表与已有SL/TP

持仓管理会查询普通挂单和Algo条件单，按symbol、positionSide、平仓方向及reduceOnly/closePosition标志核对归属。双向持仓的SELL LONG / BUY SHORT作为平仓侧，不能将BOTH或反向开仓单混入。未能确认用途的订单单独列出；查询失败、缺字段和过期不等于未设置。保护数量采用单笔已核验订单的最大可覆盖数量，不将可能相互取消的条件单相加冒充全仓保护。挂单存在和触发价越过都不证明已经执行。标记价触发与合约价触发分开标识，限价单保留触发价及委托价，移动止损只显示激活价和回调比例，不伪造实时SL。

选择持仓后，现有主图叠加实际均价、账户标记价、已设SL/TP；深度审阅通过后可查看结构校验过的建议SL/TP，以及原计划参考。实线表示已设参考、虚线表示未执行的建议、点线表示原计划或旧数据；三种来源可以独立显示。绘制复用KeyLevelOverlay原生水平线和TradeOverlay背景区域，没有新增一套行情图。色带按当前视口分为左侧已设、右侧建议，从快照标记价计算剩余价格风险及目标空间，不虚构开仓时间、不表示全仓成交收益、不计费用。密度限制只隐藏图上部分线条，完整已读数据仍在持仓订单面板。

普通账户更新会被动刷新持仓图，不重置用户缩放/平移或自动调用模型；返回实时图表后不会被轮询强制打开。审阅结果始终保留账户和行情原快照；过时建议隐藏于当前图，可主动查看原审阅快照并对照其当时标记价、已设单和建议。账户异常时图中旧线变为灰色参考，暂停当前风险区域。现有接口没有提供实际成交时间和实时移动止损跟踪价，因此没有补造这些信息。

已有固定SL只有在覆盖当前整笔数量、引用真实已确认5m主要保护并通过同一ATR风险校验后，才可沿用来审阅TP；模型仍须引用该保护结构。无需为了输出目标强制提出新SL。交易所接受挂单不等于保护结构合理，过近、未知触发类型、部分覆盖或过期订单不能绕过风险校验。

订单接口依据：[Binance普通挂单](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/trade#current-all-open-orders-user_data)、[Algo条件挂单](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/trade#current-all-algo-open-orders-user_data)。两者无symbol时各有40请求权重，当前后端15秒轮询共约320权重/分钟用于订单读取，仍共享现有时间校准、限流退避、请求去重与12秒总期限。


### 当前持仓图表与主动审阅

持仓管理中的「图表查看当前持仓」复用公共实时行情（包括当前未收盘 K 线），并保留账户轮询同步的实际均价、标记价及交易所已有 SL/TP；标记价与合约最新价不是同一报价。结构提取只使用已收盘数据，1m/5m/15m 分别按实际周期计算；切换更高图表周期时仍显示实时行情与持仓价位，不把5m结构改名为高周期结构。行情暂停或请求失败会明确显示状态。点击「查看原审阅快照」才冻结到原始分析行情。

后台本地规则刷新不再禁用「深度审阅此持仓」。主动审阅依次显示账户同步、多周期准备、截图、模型调用和校验阶段，可取消；错误在按钮旁显示，并允许重试。账户过期、关键持仓字段不完整或已有其他分析时仍会阻止请求，并显示原因。没有可用上下文时，主动审阅先重新获取有效多周期数据，继续沿用现有结构、引用和价格风险校验。

审阅完成后图表保持实时模式，建议文本保留原始账户/行情时间锚点；分析期间账户或行情更新会将旧结果标记为过时，不会把旧建议价格当作当前有效建议叠加。原始建议与原始行情可主动查看，不会自动修改真实止盈、止损或执行交易。自动化测试使用注入的行情、账户与模型响应，不调用真实账户交易接口或实际模型额度。


### 在哪里查看开仓和持仓建议

- **开仓机会**：右侧的「快速扫描」使用本地规则筛选候选，不调用模型；「深度分析」使用同一套有效多周期输入，请所选 AI 审阅候选和矛盾。使用模拟分析来源时会明确标记模拟审阅。两种结果均显示在按钮下方，列出入场区域、SL、TP、R 和未满足条件；没有合格机会则等待。规则候选、AI 保留与 AI 建议等待分别标记。深度分析完成后留在结果处，点击「定位当前候选」才切到相应图表。
- **我的持仓**：用于 Binance 同步的实际持仓。选择仓位后，点击「深度审阅此持仓」，建议显示在按钮下方。实际均价与标记价优先展示，账户与保证金字段收在可展开明细中。原账户和行情快照的有效性、计划关联及精确价格校验保持不变。
- **单周期解读**：保留为图表结构研究入口，不与多周期开仓候选或真实持仓管理混用。
